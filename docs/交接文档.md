## 1. 项目概述

一个 Windows 桌面 GUI 工具，用于检查电子书（EPUB / MOBI / AZW / AZW3 / PDF）的完整性。三件事：校验一本书是否完整、判断修复版相对原版改了什么、检查合集是否覆盖所有分册。

v3.0 起界面从 tkinter 换成 **PySide6（Qt）**，代码拆成「纯逻辑引擎 + Qt 界面」两个文件。

## 5. 代码架构

### 5.1 epub_core.py（引擎，无 Qt）

EPUB 结构：local / resolve / rel_to_opf / fmt_size / is_text_media / is_image_media / get_opf_path / parse_opf / opf_text_images / normalize_text / extract_toc / image_refs / cover_hrefs / css_url_refs

单文件与对比：check_single(path)→(report, problems) / check_pair(pathA, pathB)→report

MOBI/AZW：is_mobi_file / mobi_records / mobi_first_image_index / _jpeg_size / _is_page_jpeg / mobi_images

图片哈希与匹配：dhash / hamming / _thumb / _mad / _find_match

PDF：is_pdf_file / pdf_page_count / pdf_images

合集与识别：detect_book(path)→(kind, info) / book_image_dhashes(path) / book_fulltext(path) / check_collection(collection_path, sources)→report

比对层（v2 引入）：FMT_BY_EXT / book_format / _norm_rel / _text_digest / _cache_key / book_manifest / book_info_cached（单飞 + 摘要缓存，失败不缓存）/ compare_books(a, b) → {status, summary, reason, detail} / STATUS_* 状态常量与 STATUS_TEXT 图标文本 / STATUS_COLOR 文字颜色表（浅色，深色主题下可读）

配对层（v3.1 新增）：_dominant_dir(paths) 取合集里最常见的顶层目录；match_books(ta, tb) 先按归一化路径配对，剩余再按内容 md5 一对一消耗反查，返回 path_same / path_diff / content_same / only_a / only_b / detail

调度：class TaskRunner(tasks, emit, workers=3)。tasks 是 [(idx, base, check, same)]，emit 收到**元组**：("stage", idx, text) 或 ("row", idx, status, summary, reason, elapsed, done, total)。cancel() 只把 pending 标 cancelled，正在跑的收尾时报「已中断」。

## 6. 核心算法说明

### 6.1 单文件检查（check_single）
- zip CRC 校验（zipfile.testzip）
- OPF 版本、manifest 缺文件、spine 无效 idref
- 断链图片（解析每个 xhtml 的 img src，resolved 不在 namelist 内）
- 孤儿图片（仅「提示」，不计入 problems；已用 cover_hrefs + css_url_refs 排除封面和 CSS 引用）
- 章节列表（spine 顺序 + nav/ncx 标题）

problems 只统计 4 类硬错误：CRC 失败 / manifest 缺文件 / spine 无效 / 断链图片。

### 6.2 双书比对（compare_books）
- 同格式 EPUB：资源清单（文本 set + 图片 set，按 `_norm_rel` 归一 .xhtml/.htm→.html）逐项比，再对共同文本文件算字符数与 md5 摘要判同/异
- 文本用 `_text_digest` 只存 (字符数, md5)，缓存不存全文，避免大书撑爆内存
- 路径配对只能配到「同名文件」，单卷（章节在根）vs 合集（章节在 `book_00N/`）会同名只剩 `toc.ncx` 一个 → v3.0 及以前直接判「存在差异」，v3.1 起改走内容兜底：
  - 先用 `match_books` 路径配对，配不上的再按 md5 一对一消耗反查（`content_same`）
  - 判定顺序：全无差异 → 一致；`not only_a and content_same` → **合集内含**（基准这本的章节在合集里都找得到，摘要会写「N/M 个文本在合集 book_00N 中找到」）；有内容匹配但仍有未匹配 → 部分一致；否则存在差异
  - 完全未匹配（only_a 非空且无 content_same）→ 存在差异
- 跨格式（EPUB↔MOBI/PDF）或两边都是 MOBI/PDF：一律 `无法比对` 并写明原因（现在没有像素/文本跨格式对齐能力）
- 结果缓存 key = (abspath, st_size, st_mtime_ns)，失败结果不进缓存
- `detail` 字段给详细报告用：列出「内容相同但路径不同」与「同路径但内容不同」的逐条对应，最多 300 行

### 6.3 合集完整性检查（check_collection）
输入：合集 1 本 + 分册 N 本，自动 detect_book 识别图片版/文字版。

图片版：每册每页算 dhash + 32×32 灰度 thumb，在合集页里 _find_match 找最佳匹配（numpy 全量 MAD；无 numpy 走 top-K dHash）。MAD<=8 判同页；否则按已匹配对的 median 偏移估位置，该位置也未被匹配则判「疑似降质」而非缺页。

输出：缺页 / 缺章 / 多余页 / 重复页（MAD≈0）/ 疑似降质页。

### 6.4 页面图回退（v3.3）

触发条件：`_no_meaningful_text(ta, tb)` —— 任一侧 `_text_chars()`（只累加 ≥200 字的章节）少于 `TEXT_MIN_BOOK=1000` 字。

流程：`page_hashes(path)` 取每页 dhash(9x8) + 32x32 灰度缩略（按 `_cache_key` 缓存，按总页数上限 `_IMG_CACHE_PAGES=12000` 淘汰，约 12 MB）→ `match_pages(ha, hb)` 用 `numpy.bitwise_count` 对 dhash 做分块 XOR 取 top-8 候选，再用缩略图 MAD ≤ `MAD_THRESHOLD(8.0)` 确认，按 MAD 升序贪心一对一；之后做重复页复配（剩余页对全体取 argmin，≤ `PAGE_DUP_MAD(2.0)` 计入 `dups`）→ `coverage = min(cov_a, cov_b)`。

判定（`_compare_pages`，v3.4 起先判包含关系）：两侧都无剩余 → `一致`；`cov_a ≥ PAGE_CONTAIN_COVERAGE(0.95)` 而 `cov_b` 不足 → `合集内含`（基准基本全在待检里，摘要注明剩余几页对不上）；`cov_b ≥ 0.95` 而 `cov_a` 不足 → `合集内含`（反方向）；`cov ≥ PAGE_FULL_COVERAGE(0.99)` → `一致` 并在摘要注明「N 页对不上（多半是渲染/裁边差异）」；`cov ≥ PART_COVERAGE(0.3)` → `部分一致`；否则 `存在差异`。

文字路径同理：`coverage_stats(m, ts, side="b")` 算待检侧覆盖率，基准=合集、待检=单卷时也能判 `合集内含`。

两侧页面图都少于 3 张时不走回退，仍按原格式分支报「无法比对」。

## 8. 已知坑与教训（改代码前必读）

1. **img src 正则**：含引号的原始字符串要写三引号 raw 串（r'''...'''），否则 SyntaxError。
2. **往 JS/模板串里写 Python 源码**：反斜杠要 \\；稳妥做法是先单独写临时文件再按文本拼接。
3. **Qt 线程**：worker 线程只能 emit 信号，绝不能碰控件或创建 QTimer（会报 "Timers can only be used with threads started with QThread"）。界面更新一律走 Bridge 信号。
4. **QSettings 注册表**：本机沙箱写 `HK_CURRENT_USER` 返回 AccessError，因此用 `SETTINGS_FILE`（程序同目录 epub_checker.ini）。改回注册表前先确认有写权限。
5. **TableView 默认降序**：`setSortingEnabled(True)` 后视图按第一列降序排，双击行会取错数据，必须显式 `sortByColumn(0, Qt.AscendingOrder)`；取行数据一律 `proxy.mapToSource` 后用源模型行号。
6. **tempfile.mkdtemp() 0o700**：在 DSH 沙箱里建的目录连自己都写不进去，测试夹具用工作区内 `os.makedirs(..., mode=0o755)`。
7. **offscreen 虚拟屏 800×800**：测试里窗口尺寸不能超过它，否则 restoreGeometry 会被夹到 798×774。
7b. **列宽要按版本门控**：`_load_settings` 里旧 ini 会把 v3.0 的窄列宽恢复回来，导致「差异摘要」又被截断；现在用 `ui_version` 对比 VERSION，版本不同就不恢复列宽。
7c. **深色主题文字**：结论列用 `STATUS_COLOR` 浅色表（`lightness()>120`），失败行底色 `#4a1f24`（`lightness()<100`），不要用 Qt 默认前景色（在深色系统主题下发黑、看不清）。
8. **numpy uint8 相减回绕**：MAD 计算要 astype(int16) 再相减。
9. **dHash-only 会误报缺页**：灰度 JPEG（mode L）→ 调色板 PNG（mode P）重编码会改 dHash，必须用像素 MAD 兜底。
10. **MOBI 178×240 书架缩略图会被当页提取**：用 _jpeg_size 解析 SOF 取宽高，最短边 <300 丢弃。
11. **detect_book 把漫画误判为文字版**：nav.xhtml 与 toc.ncx 会被 is_text_media 算进文本数。判据只用「平均文字长度 < TEXT_MIN_AVG」。
12. **写 .bat 的硬性要求**：必须 GBK(936)+CRLF，write 产出的 LF+UTF-8 会让 cmd 崩。

13. **thumb 是 bytes 不是 list**：`book_image_dhashes` 返回的第三项是 `bytes(1024)`，转 numpy 要用 `np.frombuffer(t, dtype=np.uint8).reshape(32, 32)`，直接 `np.array(t)` 会得到 0 维对象数组。
14. **`page_hashes` 对不存在的路径静默返回 `[]`**：调试时如果路径写错只会看到「0 页」，看不出报错；排查页面图比对先打印 `len(page_hashes(path))`。
15. **重复页会骗过一对一匹配**：同一页在书里出现两次时，第一份配掉后第二份会落进「仅一侧有」，看起来像缺页；必须做重复页复配 + 覆盖率取 min，否则真实书只能到 97.6% 判「部分一致」。

16. **页面图缓存挤掉合集**：原来 `_IMG_CACHE` 超过 4 本就 `clear()`，12 卷对 2147 页合集时几乎每轮都要重解 2147 张图（13 秒/对）。改成按总页数上限 12000 淘汰后，第一对 13.8 秒、其余每对 1.5 秒。
17. **包含关系不能用 min 覆盖率判**：`coverage=min(cov_a,cov_b)` 对「199 页单卷 vs 2147 页合集」只有 11%，会被判成差异/部分一致；必须单独看单侧覆盖率（`cov_a≈1` 或 `cov_b≈1`）判 `合集内含`。
- **目录 href 是相对 nav 文件所在目录的**，不是相对 OPF 目录：`read_toc_tree` 现在统一转成 zip 内全路径（`base = dirname(nav_full)` 再 join）。真实书 `OEBPS/Text/nav.xhtml` 里写 `cover.xhtml` 时，按 OPF 目录拼会得到 `OEBPS/cover.xhtml`（不存在）→ 合并自检必报「目录项指向不存在的文件」。合成夹具的 nav 都放在 OPF 同层，永远造不出这个坑。
- **合并子书可能带死链**：`_collect_book` 对每条目录项做「原路径 → OPF 目录拼接 → 小写映射」三级兜底，仍找不到就跳过（不再把死链塞进合并目录），书级入口按 spine 第一项取，取不到退回第一节目录项。

## 9. 待办（Open Objectives）

- **PDF / 文字版 MOBI 的逐字比对**（原 m00788，仍未做）：现在 PDF 只报页数与内嵌图片数，MOBI 只提图片不提文字，跨格式一律「无法比对」。已探明：本机 Calibre 9.18（`C:\Program Files\Calibre2\ebook-convert.exe`）可在 1~2 秒内把无 DRM 的 AZW3/AZW 转成 txt（实测 40353 字符 / 690137 字符），但 PDF 转 txt 对纯图片 PDF 无意义且极慢（实测 0 字符 / 69.6 秒）；PDF 文本需 PyMuPDF 之类。方案：做成「检测到 Calibre 才启用」的可选文本比对，且要处理 DRM 与加密 EPUB。
- **加密 EPUB（DRM）识别**：core 目前不判 DRM，遇到加密书会以损坏/无法比对收场，可在 book_manifest 里加 encryption.xml 检测给更准的提示。
- **合集检查的取消**：`check_collection` 是单次同步调用，没有中断点，「取消」只能等当前步骤结束；要真正可中断得在 core 里加分片回调和取消标志。
- **阈值可配置**：100/1000/5000 的任务量提示与 MAD/文本阈值目前写死，可考虑放进 ini。

## 21. v3.15 拖放修复

### 21.1 问题

- 用户反馈「合并功能不支持拖拽文件」。实测对比页同样不灵。
- 根因：`BookPanel` 90% 面积是 `QListView` 的 viewport，`setAcceptDrops(False)` 让事件停在 viewport 上，不会冒泡到面板自己的 `dropEvent`；此前只在 panel 上装了 `dragEnterEvent`/`dropEvent`。
- 次因：`MergeDialog.ed_title`（QLineEdit）默认收拖放，把落下的文件当文本插进书名框。

### 21.2 修法

- `BookPanel.eventFilter` 接管 `self.view.viewport()` 的 `DragEnter`/`DragMove`/`Drop`：有 URL 就 accept，Drop 时收集本地路径发 `add_paths`；「点空白处加文件」分支保留。
- `MergeDialog.ed_title.setAcceptDrops(False)`；`MergeDialog.dropEvent` 末尾补 `acceptProposedAction()`。

### 21.3 测试

- `_build/v3/test_drop.py` 4 项：视口 DragEnter 被接受、视口 Drop 加进模型、合并页列表 Drop 加进模型、书名框不吃拖放。
- 坑：`QDragEnterEvent`/`QDropEvent` 只持 `QMimeData` 裸指针，Python 侧不保活会整进程静默崩溃；测试里用模块级 `ALIVE` 列表延长生命周期。
- 全量：`Ran 167 tests / OK (skipped=1)`。

## 23. v3.18 中英双语（界面 + 报告正文）
