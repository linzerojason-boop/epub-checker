## 一、总体结论

引擎层（`epub_core.py`）设计思路清晰：只读解析、清单级比对 + 页面图回退、单任务失败隔离、写盘先 `.part` 再自检再 `os.replace`，这些都是正确的工程决策。**单文件检查、合并 EPUB、页面图比对、任务调度这几块实测可用**，486MB 大文件单检 0.7 秒，性能没有问题。

但存在 **2 个让功能直接失效的 P0 缺陷**：

1. `compare_books` 在「内容高度重叠但非完全一致」区间（覆盖率 ≥ 30%）一行 `%d` 格式化，**必抛 TypeError** —— 也就是「原版 vs 修复版」这个核心场景永远显示「⛔ 失败」；
2. 「合集检查」界面把 `check_collection` 的单字符串返回值当二元组解包，**该页面 100% 显示「检查失败：ValueError」**。

另有 4 个 P1 级缺陷（结论过滤、目录检查误判、生成目录三类书不可用、替换封面写出非法 OPF），其中前两个多为一行改动。

## 三、P0 级缺陷（建议立即修）

### P0-1 「原版 vs 修复版」比对必定失败：`%d` 塞了字符串

**位置**：`epub_core.py:2347`（值来源）与 `2386`（出错点）

```python
# 2347
pct = "100" if cov >= 0.9995 else ("%.1f" % (cov * 100))   # pct 恒为 str
...
# 2386
bits = ["内容覆盖 %d%%" % pct]      # %d 收到 str → TypeError
```

**触发条件**：`cov >= PART_COVERAGE(0.3)`，且既没命中「完全一致」也没命中两个「合集内含」分支——即**两本书内容大部分相同、只有少量差异**的情形（判断修复版改了什么，正是这一档）。

**实测证据**（真实书 `Hello, Hello and Hello` 原版 vs `_修复版`，两册均生效）：

```
1  Hello, Hello and Hello (葉月文) | Hello, Hello and Hello_修复版.epub | ⛔ 失败
   TypeError: %d format: a real number is required, not str
```

直接调用同样抛：

```
抛异常: TypeError %d format: a real number is required, not str
```

**副作用**：`2399` 行 `status = STATUS_PART if cov >= PART_COVERAGE else STATUS_DIFF` 成为不可达代码；界面「详细报告」页也会追加一行「逐条差异生成失败：TypeError: …」。

**修法**：`%d` → `%s`（一处）。修完建议回归：原版/修复版应给出「△ 部分一致 / 内容覆盖 99.x% + N 个内容不同」。

### P0-2 「合集检查」整页 100% 失效：解包了一个字符串

**位置**：`epub_gui_qt.py:501`

```python
def work():
    try:
        rep, _probs = core.check_collection(coll, srcs)   # ← 解包成两个值
    except Exception as e:
        rep = f"检查失败：{type(e).__name__}: {e}"
    self.report_ready.emit(rep)
```

而 `check_collection`（`epub_core.py:1690`）所有出口都是 `return "\n".join(L)`，**只返回一个字符串**。

**实测**：直接调用返回 `type = str, len = 2741`；界面侧必然走到 `except`，提示区永远显示：

```
检查失败：ValueError: too many values to unpack (expected 2)
```

**修法**：`rep = core.check_collection(coll, srcs)`。

引擎本身没问题——1 卷（153 页）对 818 页合集实测 8.8 秒，结论「所有分册内容均已在合集中找到，未发现缺失」，匹配 152/152、降质 0、缺失 0。

## 四、P1 级缺陷

### P1-3 结论过滤：「不一致」永远筛不出东西，「一致」混进三类

**位置**：`epub_gui_qt.py:1452`（下拉项来源）、`1211`（`setFilterKeyColumn(4)`）、`1669-1673`（`setFilterFixedString`）；对照 `core.STATUS_TEXT`

下拉项是**原始状态名**，单元格显示的是**带图标文案**，`QSortFilterProxyModel` 默认按显示文本做子串匹配：

| 下拉项 | 单元格实际文本 | 是否能匹配 |
|---|---|---|
| 一致 | `✓ 一致` | ✅ 但 `≈ 合集内含（内容一致）`、`△ 部分一致` 也含「一致」→ 一起显示 |
| 不一致 | `✗ 存在差异` | ❌ 不含「不一致」三个字 |
| 合集内含 | `≈ 合集内含（内容一致）` | ✅ |
| 失败 / 跳过 / 已取消 / 无法比对 | 前缀不同、词相同 | ✅ |

**offscrren 实测**（造 8 行覆盖全部状态）：

```
选「全部」  -> 8 / 8
选「一致」  -> 3 / 8      ← 应为 1
选「不一致」 -> 0 / 8      ← 应为 1
```

**连带影响**：`filter` 会持久化到 `epub_checker.ini`，一旦被存成「不一致」，下次启动就是空表。

**修法**：模型加 `Qt.UserRole` 返回原始 `status`，用 `QSortFilterProxyModel` 子类 + `filterAcceptsRow` 按 UserRole 精确比较（比继续操作显示文本更可靠）。

### P1-4 目录检查大面积误判：`normalize_title` 把「第X章」整条清空

**位置**：`epub_core.py:549`（生成空串）＋ `561-566`（空串被跳过）

```python
# 549
s = re.sub(r"第\s*[0-9一二三四五六七八九十百零〇]+\s*[章节回卷部篇话集]", "", s)
```

对「第一章」「第01话」这种**只有编号、没有副标题**的常见写法，剥完就是空串；`toc_diff` 里 `if not nt: continue`，于是这类条目永远配不上。

**实测**（用书里现成目录回填成清单，理应「一致」）：

| 书 | 结果 |
|---|---|
| 《你好，世界》 | `书内目录 12 条 / 清单 12 条 / 匹配 5 条`，另报 7 条「清单有、书里没有」+ 7 条反向误报 |
| 《污秽不堪的你最惹人怜爱 (1)》 | `6 条 / 6 条 / 匹配 1 条` |
| 《含羞草的告白-2》（标题带副标题） | `8 / 8 / 8`，正常 |

即：**书越好读（章节标题越干净），这个功能越不可信**。

**修法**：剥编号后若结果为空，保留编号本身（或退回「去标点小写」的整串）作为 key；不要产出空归一化值。

### P1-5 「生成目录」对三类真实书不可用，且错误信息误导用户

三处独立成因，都集中在 `apply_toc`（`1011-1042`）、`pair_toc_items`（`654`）、`_rel_href`（`701-703`）、`spine_docs`（`455-476`）。

| 书型 / 实例 | 实测报错 | 成因 |
|---|---|---|
| 单文件多锚点（Calibre 产物，如《三日间的幸福》：`text00000.html#filepos…`） | `清单第 2 行与前面的条目指向同一个文件：text00000.html` | `read_toc_tree` 把 `#fragment` 丢掉；`pair_toc_items` 又禁止同一目标重复 → 18 条目录只对应 2 个文件，必然冲突 |
| nav 里含 `cover.xhtml`（如《Hello, Hello and Hello_修复版》） | `清单第 1 行的目标文件在书里不存在：cover.xhtml` | 预填清单来自 nav（含封面页），而 `spine_docs` 把 `cover.xhtml`/`nav.xhtml`/`toc.xhtml` 当非正文剔除 → 预填→生成自相矛盾，用户必须手工删行 |
| nav / ncx 位于子目录（`OEBPS/Text/nav.xhtml`、污秽(1) 的 `xml/vol.nav`） | `目录项指向不存在的文件：OEBPS/Text/Text/chapter-1.xhtml` | `_rel_href` 只把 `\` 换成 `/`，按 OPF 目录算出的 href 原样写进子目录里的 nav/ncx |

**实测细节**

- 单文件多锚点：`spine_docs = ['text00000.html','text00001.html']`，目录 18 条，`pair_toc_items -> entries=0 errs=[清单第 2 行与前面的条目指向同一个文件…]`，**任何清单都过不去**。
- 子目录 nav：即使只给 3 条最小清单（`第一章 -> chapter-1.xhtml` 等），也报 3 条 `目录项指向不存在的文件：OEBPS/Text/Text/chapter-N.xhtml`，输出被删除、返回 `None`。
- 好消息：这条路径**没有静默产出坏书**——`verify_epub` 挡住了。设计是对的，缺的是「写得对」。

**修法建议**

1. `_rel_href(href, opf_dir, target_full)` 改为 `posixpath.relpath(resolve(opf_dir, href), posixpath.dirname(target_full))`，nav 与 ncx 各自算各自的相对路径；
2. 预填清单按 `spine_docs` 过滤掉封面/目录页；或让 `pair_toc_items` 对这类目标给「跳过」而不是「错误」；
3. 锚点目录：要么把 `#fragment` 随标题一起写回（`<a href="file.html#pos">`），要么在检测到「多条目录项共用同一文件」时明确提示「该书为单文件多锚点结构，暂不支持重建目录」。

### P1-6 替换封面会写出违反 OPF 唯一 ID 约束的文件，而自检全部放过

**位置**：`epub_core.py:1074-1077`（固定传 id）＋ `787-880`（`patch_opf` 插入 manifest 不查重）

```python
new_opf = patch_opf(opf_bytes, dir_, title=title, uid=uid,
                    cover={"href": img_full, "id": "cover-image",   # ← 固定值
                           "media_type": media},
                    cover_page={"href": page_full, "id": "cover-page"})
```

**实测**（《三日间的幸福》，原书已有 `id=cover-image` 的 `Image00000.jpg`，`replace_cover=True`）：

```
apply_cover -> True problems = []
verify_epub(out) = []                    ← 自检通过
重复 id: ['cover-image']                 ← manifest 非法
带 cover-image 属性的条目:
    ('cover-image', 'Image00000.jpg')
    ('cover-image', 'images/cover.jpg')   ← 两个 cover-image
check_single(out) probs = 0              ← 单检也认为没问题
```

后果：EPUBCheck 会报 duplicate ID；不同阅读器可能仍取旧封面；文件体积白带一张原封面。另外 spine 首位无条件插 `cover-page`，原书已有封面页时会变成两个封面页。

**修法**

1. 复用时先取 `cover_hrefs` / meta 里已存在的 cover id，新 id 与 manifest 全量 id 去重后再插入；
2. 插入 `cover_page` 前检查 spine 首项是否已经是封面类 xhtml（文件名含 `cover` 或 `properties` 含 `cover`），是则复用/跳过；
3. 若确实要「替换」，就把旧 cover 条目与旧 `cover-image` 属性一并去掉，而不是叠加。

### P2-8 换一本不刷新预填清单

## 六、P3 级问题（小隐患）

- **P3-12 合并输出命名**：`default_merge_dst`（`2749-2758`）主分支用 `re.sub(r'[\\/:*?"<>|]+', "_", …)` 清洗，撞名分支却直接用原始 title。实测标题「第1/2卷」且同名文件已存在时返回 `…\合并_第1/2卷_2.epub` —— 写入会落到不存在的子目录而失败。两条分支应复用同一个清洗函数。
- **P3-13 缓存无上限**：`_CACHE`（`1905`）与 `_KEY_MU`（`1911`）只增不删；只有图片缓存 `_IMG_CACHE` 按 `_IMG_CACHE_PAGES=12000` 页淘汰。长会话/几千任务时内存与锁对象只涨不降。
- **P3-14 ZipFile 未统一 `with`**：`check_single`(`1474`)、`check_pair`(`1598-1599`)、`book_fulltext`(`1422`)、`book_manifest`(`1946`)、`detect_book`(`1303`)、`book_image_dhashes`(`1398`) 都是裸 `zipfile.ZipFile(path)`。`ZipFile` 有 `__del__` 会兜底关闭，但批量跑时短期句柄偏高，建议统一上下文管理。
- **P3-15 大批量耗时估算**：`_confirm_big`（`1630-1639`）按 `total * 0.02` 秒估算，实测大书一对 9~10 秒（152 页 vs 818 页），5000 任务会提示「约 100 秒」，严重低估。
- **P3-16 分发脚本硬编码**：`epub_checker.bat` 写死 `C:\Users\Jason\.dsh\dsh-runtimes\…\python.exe`，换环境即失效；exe 版 `settings_path()` 落在 exe 同目录，程序若放进只读目录（如 Program Files），设置保存会失败。
- **P3-17 运行中未锁定合并入口**：`_lock_ui`（`1762-1773`）禁用了 `btn_collection` / `btn_edit` / 导出 / 过滤，但模式栏的「合并 EPUB…」仍可点，可在比对运行中切到合并页。
- **死代码/半死代码**：`apply_both`（`1090`）、`write_epub_variant(cover_first=…)`（`882`）、`open_merge_dialog` / `open_collection_dialog`（v3.7 改为 `_goto` 后仅作兼容）、`_compare_pages(path_a, path_b, …)`（`2234`）的两个入参未使用。
